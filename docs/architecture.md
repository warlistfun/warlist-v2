# Architecture (As Built)

WARLIST 2.0 has a resource-free application composition core, strict compiler configuration, and repository-boundary validation.

```text
test -> src/app/config.ts
     -> src/app/ports.ts
     -> src/app/create-application.ts
     -> src/app/create-http-app.ts
     -> src/app/bootstrap.ts
     -> src/interfaces/worker-ipc/contract.ts
     -> src/modules/whatsapp/application/worker-diagnostics-service.ts
     -> src/modules/whatsapp/application/worker-runtime-service.ts
     -> src/modules/whatsapp/application/worker-ownership-service.ts
     -> src/modules/automation/application/automation-evaluator.ts
     -> src/modules/automation/application/inbound-message-normalizer.ts
     -> src/shared/version.ts
     -> scripts/check-repository-boundary.mjs
```

`createApplication()` accepts explicit configuration and ordered lifecycle dependencies. Startup occurs in registration order, cleanup obligations are registered before each start attempt, failed startup rolls them back, and shutdown occurs in reverse order. Failed cleanup remains registered for retry and blocks restart. Repeated start/stop calls are idempotent. Tests supply deterministic no-op/in-memory implementations for logger, metrics, clock, ID generation, repository, and worker-runtime boundaries.

There is no HTTP server, worker process, WhatsApp connection, provider adapter, timer, listener, or deployment artifact. Concrete database behavior is limited to PostgreSQL 16 lifecycle and pooled business repositories plus a versioned migrator, all exercised against temporary synthetic local clusters; no hosted database is configured or contacted. Future modules follow the modular-monolith and ports/adapters decisions in the ADRs and migration plan, but they are not as-built behavior.

Worker IPC protocol v1 is a resource-free contract boundary. Parent commands and child acknowledgements/errors carry request, correlation, tenant, generation, and child identities. Decoders accept exact runtime-validated schemas, return immutable values, reject unsupported versions or unknown message types with stable errors, and restrict child errors to canonical safe code/message/retryability combinations. The contract does not yet fork a worker, schedule a timeout, or implement runtime lifecycle orchestration.

`WorkerDiagnosticsService` is an application-level boundary over an injected sink. It emits immutable, discriminated command and ownership events with whitelisted fields only: bounded correlation/tenant/generation/child identity plus closed command outcomes or ownership state/quarantine status. Malformed values, extra properties, raw errors, IPC/config payloads, and internal state are not forwarded. Sink failures are best-effort and cannot change command or ownership behavior. No concrete logger, metrics adapter, process integration, or other sink is composed yet.

`WorkerRuntimeService` is a transport-neutral command lifecycle over IPC v1. It serializes commands per tenant, deduplicates identical pending requests, requires matching decoded ACK/error identity, and fails closed through an injected bounded-timeout scheduler. Matching acknowledgements, canonical child errors, timeouts, transport unavailability, and runtime shutdown produce safe terminal command diagnostics from the pending parent identity without forwarding raw errors or payloads. Its frozen debug snapshot exposes only pending command type, correlation, tenant, generation, and child identity; request IDs and configuration payloads remain private. Deterministic tests use the existing manual transport and scheduler as a synthetic harness for START, APPLY_CONFIG, STOP, delimiter-safe deduplication, cross-tenant timeout/unavailability isolation, stale-identity rejection, and timeout retry: a late ACK/error from an expired request cannot settle a retry with a new request identity. Transport startup and shutdown are bounded; a rejected or timed-out lifecycle operation leaves cleanup explicitly incomplete, blocks restart, and can be retried through stop. Shutdown and exact child invalidation reject matching pending commands, and invalidated queued continuations cannot send later. The service remains resource-free until future concrete child-process, scheduler, and diagnostics adapters are composed.

`WorkerOwnershipService` is a resource-free per-tenant ownership state machine layered over that command boundary. It allocates monotonically increasing generations, binds ownership to an opaque child identity, and accepts terminal child-exit evidence only when both match the current owner. Exact current-child exit invalidates that child's pending and queued commands before ownership is released, so a late acknowledgement cannot restore command authority. It emits safe correlated `STARTING`, `RUNNING`, `STOPPING`, and `STOPPED` projections, including quarantine status, for accepted ownership operations and exact terminal evidence. A config update is forwarded only for a confirmed non-quarantined `RUNNING` owner, with its current generation and child identity; update failure preserves that confirmed ownership. Deterministic restart proof confirms that terminal evidence from a prior generation/child cannot alter a pending newer incarnation. Any failed start is quarantined in `STOPPING` and receives a compensating stop; ownership becomes startable again only after matching stop acknowledgement or child-exit evidence. This service neither starts a process nor consumes concrete process events.

`ActiveTenantWorkerService` is a resource-free coordinator over injected selected tenant descriptors and the ownership lifecycle boundary. It boots supplied descriptors sequentially in input order, fails at the first delegated error without invented rollback, and delegates config update and stop intents. It neither discovers active tenants nor reads persistence/configuration, creates child identities, registers application lifecycle work, or provides legacy migration/cutover behavior.

`WorkerLifecycleStateRepositoryPort` is a lifecycle persistence boundary over immutable tenant-keyed snapshots. The disposable in-memory adapter proves deterministic single-process behavior: copied frozen snapshots, prior-snapshot preservation on delegated save failure, monotonic generations, and exact-prior-snapshot `compareAndSave()`. The concrete PostgreSQL 16 adapter accepts injected server-owned tenant authorization, validates snapshots and database rows at its trust boundaries, parameterizes SQL, and uses one conditional statement to fence generation regression and conflicting same-generation transitions across independent connections. Unconditional saves permit only a newer generation or an idempotent exact snapshot. Migration `0005-delivery-claim-lease.sql` makes its current database projection use the canonical UUID business-tenant identity; migration `0001` remains historical synthetic text-identity proof. These migrations and tests run only against test-created temporary local clusters. They do not configure a hosted database, survive a real deployment restart, or establish Production readiness.

`runPostgresMigrations()` receives one explicit ordered migration list and dedicated query client. It validates descriptors before I/O, serializes concurrent runners with a transaction-scoped PostgreSQL advisory lock, records revision/name/SHA-256 evidence in `schema_migrations`, rejects applied checksum drift, and rolls back the batch when a revision fails. Migration `0002-business-foundation.sql` establishes UUID tenant identity separate from public OPS identifiers, versioned automation configuration, deterministic `PREPARED` delivery-operation identity, and bounded audit metadata with database-enforced ownership, idempotency, revision, and timestamp constraints.

`BusinessRepositoryPort` exposes separate tenant, versioned opaque-config, deterministic delivery operation/attempt, and bounded audit operations rather than a mutable tenant aggregate. Its in-memory and pooled PostgreSQL adapters share one behavioral contract, require injected tenant authorization, validate inputs and PostgreSQL rows, and return detached frozen records. Migration `0004-delivery-attempt-foundation.sql` establishes tenant-owned attempt identity. Migration `0005-delivery-claim-lease.sql` and the narrow `DeliveryClaimRepositoryPort` add one atomic PostgreSQL CAS that admits only the exact current non-quarantined UUID tenant worker, records owner/fence/lease/generation/child on the operation, and inserts one attempt bound to the winning fence while preserving any earlier prepared attempts. Migration `0006-delivery-settlement.sql` adds a bounded safe provider-message identity and a durable `SENDING` crash boundary. Exact matching operation/attempt/fence/current-worker authority moves one claimed attempt to `SENDING` before the injected sender, then to `SENT` or `AMBIGUOUS`; expired `SENDING` is recovered as `AMBIGUOUS`, never replayed, and stale identity conflicts. `createClaimGatedDeliverySender()` has no retry loop. `createDeliveryConfirmationService()` derives an explicit WIB business date and calls one pooled PostgreSQL CTE that fences the exact current `SENT` authority, persists confirmation identity, and conditionally appends one `DEBIT_CONFIRMED_DELIVERY` ledger entry. Exact replay returns canonical confirmation; a later delivery on the same date confirms without another debit. It is not a real provider adapter. Hosted Supabase, credentials, deployment, and Production behavior remain unimplemented.

`BusinessRepositoryPort` also exposes an append-only entitlement ledger. It accepts only tenant-owned, bounded integer credit/debit entries with closed types, a correlation ID, and a unique business key. An identical business-key replay returns the original immutable entry; a conflicting reuse is rejected. The balance is a direct ledger `SUM`, not mutable state. This is synthetic/disposable PostgreSQL proof only: no payment/coupon provider flow or delivery-confirmation debit is composed yet.

`TenantEnrollmentRepositoryPort` is a narrow identity foundation for one purpose-bound enrollment grant. Its in-memory adapter serializes one-use grant consumption for deterministic application tests. Its PostgreSQL adapter consumes an unexpired `TENANT_ENROLLMENT` grant and inserts the user, tenant, and exactly one `OWNER` membership in one transaction; any unavailable grant or database constraint failure rolls back the entire allocation and returns one safe enrollment-unavailable error. Strict authenticated-principal decoding exposes a tenant-authorization adapter: repository access derives solely from an exact UUID user identity and unique UUID `OWNER` memberships; cross-tenant, forged, and non-owner requests fail closed before tenant state is accessed. Migration `0009-identity-tenant-enrollment.sql` adds only users, enrollment grants, and tenant memberships. `decodeAuthenticatedPrincipal()` accepts only bounded UUID user/tenant identities and unique `OWNER` memberships; `deriveTenantAccess()` revalidates that principal and grants a requested tenant only when it is a principal membership. It has no HTTP/session/token adapter, so authentication provenance remains a future boundary. PIN/passkey credentials, sessions/token families, hosted Supabase, legacy migration, and Production behavior remain unimplemented.

`createLocalWhatsAppCredentialDirectory()` is a separate local filesystem boundary for future provider composition. It accepts an explicit canonical absolute root and exact tenant UUID, creates or reuses owner-only root/tenant directories, rejects symlink traversal and unsafe type/ownership/permissions with stable path-free errors, and returns a frozen infrastructure-only handle. It reads no environment and never reads, writes, serializes, deletes, backs up, or migrates credential payloads. No Baileys adapter or runtime is composed.

`evaluateAutomation()` is a pure, resource-free policy gate over a runtime-validated synthetic inbound message, explicit policy snapshot, optional injected minute-of-day, and optional explicit decision state. It returns one frozen closed code for bot, OPS status, time window, target group, admin trigger, keyword, entitlement, inbound dedupe, existing delivery, or acceptance in deterministic order. It does not read a clock/database, mutate configuration, inspect provider payloads, invoke workers, create delivery state, or send messages.

`normalizeSyntheticInboundMessage()` is a pure trust-boundary transformation for exact synthetic `{ groupId, senderId, text }` records. It returns a frozen evaluator-compatible value with trimmed ASCII-lowercase identifiers, NFC text, `\n` line endings, and trimmed text edges; the input remains unchanged. Bounded validation rejects extra/hidden/symbol properties, accessors, custom prototypes, invalid identifiers, unsafe control content, empty text, and oversized values with one input-independent error. It does not decode or accept Baileys/provider payloads, identifiers from customer fixtures, configuration, repositories, workers, logging, or external resources.

`createAutomationConfigMutationService()` mutates one exact field of an existing policy, derives tenant identity from trusted context, preserves unrelated configuration and Phase 5 policy fields, and loads the target group through a tenant-scoped server-side directory port. Every configured admin must exist in that current-membership projection before the expected-revision config and exact-revision outbox record commit atomically. Stale/absent configuration returns `CONFIG_VERSION_CONFLICT`; there is no synchronous rollback after worker failure.

`createAutomationConfigSyncDispatcher()` claims one due/expired exact-revision outbox record and invokes the existing active-tenant ownership/runtime boundary, which emits versioned IPC `APPLY_CONFIG` with that same revision. Matching ACK marks only the fenced claim `APPLIED`; rejection, timeout, or unavailability preserves canonical config and records bounded terminal/retry state. Expired leases are restart-recoverable. The dispatcher does not carry policy/provider payloads or launch a process.

`createActiveAutomationDecisionService()` loads canonical tenant config, normalizes one inbound synthetic message, runs early pure policy gates, loads explicit entitlement/dedupe/existing-delivery state only when needed, and returns the config revision plus frozen decision. It stops before delivery claim or external send.

`npm run debug:automation -- path/to/fixture.json` reads one explicit synthetic JSON fixture with message/policy and optional minute/decision state, normalizes it, and prints only the evaluator decision code. It has no database, worker, provider, environment, customer-data, or runtime-state lookup; malformed input produces one stable error on stderr.

`decideLegacyAdminTrigger()` is a pure synthetic characterization of one active legacy keyword decision boundary: a configured sender-specific trigger is decisive, while global keywords apply only when no sender-specific trigger exists. It accepts invented normalized identifiers/text and returns a frozen match/non-match code. It does not decode provider messages, validate membership, load or mutate configuration, invoke workers, dedupe, create delivery state, or send; it is not legacy migration/cutover.

`createHttpApp()` is an in-process adapter with versioned health/readiness routes, runtime request validation, generated request IDs, and canonical response envelopes. It does not bind a port or own network lifecycle.

`createBootstrap()` explicitly owns application startup and shutdown-signal registration through a port. It serializes transitions, unregisters handlers before shutdown, rolls back partial registration, and retains failed cleanup for retry. No `process` listener is registered at import time.

Phase 6 reconciliation is recorded in `docs/phase6-reconciliation.md`: delivery/entitlement integrity is complete for synthetic/application/disposable PostgreSQL behavior. It does not establish real WhatsApp/provider behavior, hosted Supabase, deployment, cutover, or Production readiness.

Imports must remain side-effect-free. Protected runtime/customer paths are prohibited from Git by an executable tracked-path check.

The legacy Production entrypoint does not delegate to this composition. ADR 0008 defers that integration until concrete adapter parity and an approved migration/cutover slice exist.
